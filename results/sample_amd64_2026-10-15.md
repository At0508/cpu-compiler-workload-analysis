# Local CPU workload sample

This is one correctness-checked smoke run of `loop_benchmark`, captured on 15 October 2026. It illustrates the output format and why small runs are sensitive to the machine; it is not a portable speedup claim.

## Environment and command

- OS: Windows 11, build 26200
- CPU identifier reported by the host: AMD64 Family 23 Model 104 Stepping 1, AuthenticAMD
- Compiler: MinGW g++ 16.1.0
- Flags: `-std=c++17 -O3 -Wall -Wextra -Wpedantic -fopenmp`
- OpenMP threads: 12
- Command: `loop_benchmark.exe` (default 512 matrix size, nine timed repetitions)
- Input: deterministic 512 × 512 matrix, seed 2026; nine timed repetitions after one warmup
- Timing boundary: kernel function only, using `std::chrono::steady_clock`; process startup is excluded

## Measured output

| Variant | Median (ms) | MAD (ms) | Checksum | Correct |

| Row major | 0.2296 | 0.0027 | 79.1220547557 | Pass |
| Column major | 0.6654 | 0.0098 | 79.1220547557 | Pass |

| OpenMP rows | 0.1167 | 0.0094 | 79.1220547557 | Pass |

At this size, OpenMP was fastest in this single sample, while column-major traversal was slowest. These values are specific to this host, compiler, and run; repeat with larger matrices, controlled system load, and multiple runs before drawing conclusions.
